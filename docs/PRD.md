## 1. 개요

### 1.1 프로젝트명

개인 개발 블로그

### 1.2 목적

Notion을 CMS로 활용하는 개인 기술 블로그를 만든다. 글은 Notion에서만 작성하고, 웹 사이트는 Notion 데이터베이스의 내용을 읽어 자동으로 보여준다.

### 1.3 CMS 선택 이유

- 글 작성은 Notion 편집기에서 바로 하고, 별도의 관리자 페이지를 만들 필요가 없다.
- Notion에서 글의 상태(초안/발행됨)를 바꾸면 블로그에 반영된다.
- 본문, 이미지, 코드 블록 등 편집 기능을 Notion이 이미 제공한다.

### 1.4 범위 밖 (Non-goals)

- 댓글, 좋아요, 회원가입 등 사용자 상호작용 기능
- 관리자용 글 작성/수정 UI (Notion이 그 역할을 맡는다)
- 다국어 지원
- RSS, 사이트맵 등 부가 기능 (MVP 이후 검토)

## 3. Notion 데이터베이스 구조

블로그 글은 하나의 Notion 데이터베이스에 행(row)으로 저장한다. 행 하나가 글 하나이며, 행의 페이지 본문이 글 내용이 된다.

| 속성 이름 | Notion 타입 | 설명 | 필수 |
| --- | --- | --- | --- |
| Title | title | 글 제목 | 예 |
| Category | select | 카테고리 (글 목록 필터 기준) | 예 |
| Tags | multi_select | 태그 | 아니오 |
| Published | date | 발행일 (정렬 기준) | 예 |
| Status | select | `초안` 또는 `발행됨` | 예 |
| Content | page content | 페이지 본문 (블록) | 예 |

### 3.1 공개 규칙

- `Status`가 `발행됨`인 행만 웹사이트에 노출한다.
- `초안`인 행은 목록과 상세 페이지 어디에서도 보이지 않아야 하며, 직접 URL로 접근해도 404를 반환한다.
- 목록은 `Published` 내림차순으로 정렬한다.

## 4. 기능 요구사항

### 4.1 Notion API 연동 (MVP)

- `@notionhq/client`로 데이터베이스를 조회한다.
- 조회 조건: `Status` = `발행됨`, `Published` 내림차순.
- 페이지 본문은 Notion 블록을 가져와 렌더링한다.
- 인증 정보(`NOTION_API_KEY`, `NOTION_DATABASE_ID`)는 환경 변수로 관리하고, 저장소에 커밋하지 않는다.
- Notion API 호출은 서버에서만 수행한다(클라이언트에 API 키가 노출되지 않도록).

### 4.2 글 목록 (홈)

- 홈 화면에 최근 발행된 글을 목록으로 보여준다.
- 각 항목에 제목, 카테고리, 태그, 발행일을 표시한다.
- 항목을 누르면 상세 페이지로 이동한다.

### 4.3 글 상세 페이지

- URL은 `/posts/[slug]` 형태로 한다. `slug`는 제목 기반 또는 Notion 페이지 ID 기반으로 정한다(구현 시 결정, 아래 열린 질문 참고).
- 제목, 카테고리, 태그, 발행일과 본문을 표시한다.
- 본문의 주요 블록(문단, 제목, 목록, 코드, 이미지, 인용, 구분선)을 렌더링한다.
- 존재하지 않거나 `초안`인 글은 404 페이지를 보여준다.

### 4.4 카테고리별 필터링

- 카테고리 페이지 `/categories/[category]`에서 해당 카테고리의 글 목록을 보여준다.
- 카테고리 목록은 Notion 데이터베이스의 `Category` 옵션에서 가져온다.
- 홈 또는 헤더에서 카테고리로 이동할 수 있어야 한다.

### 4.5 검색

- 제목과 태그를 기준으로 글을 검색한다.
- 검색어 입력 시 목록을 즉시 걸러서 보여준다.
- 검색 결과가 없을 때 빈 상태 메시지를 보여준다.
- 검색 방식(클라이언트 필터링 vs 서버 조회)은 글 수와 Notion API 호출 횟수를 보고 구현 시 결정한다.

### 4.6 반응형 디자인

- 모바일, 태블릿, 데스크톱에서 모두 읽기 쉬운 레이아웃을 제공한다.
- 본문 너비는 가독성을 위해 제한한다.
- 기존 `main-nav` / `mobile-nav` 구조를 활용해 내비게이션을 구성한다.
- 다크 모드는 기존 `theme-provider`를 사용하며, 지원 여부는 MVP 이후 확정한다.

## 5. 화면 구성

| 화면 | 경로(안) | 내용 |
| --- | --- | --- |
| 홈 | `/` | 최근 글 목록, 검색 입력 |
| 글 상세 | `/posts/[slug]` | 글 제목, 메타 정보, 본문 |
| 카테고리 | `/categories/[category]` | 카테고리별 글 목록 |

공통 레이아웃: 헤더(로고, 내비게이션, 테마 토글), 푸터.

---

## 6. 비기능 요구사항

- **성능**: Notion API 호출을 줄이기 위해 서버 컴포넌트에서 데이터를 가져오고, 캐싱(ISR 또는 `revalidate`)을 적용한다.
- **보안**: API 키는 서버에서만 사용한다. 초안 글의 내용이 외부에 노출되지 않아야 한다.
- **접근성**: 시맨틱 HTML, 충분한 색 대비, 키보드 탐색을 지원한다.
- **코드 품질**: 저장소의 `npm run check-all`(타입, 린트, 포맷 검사)과 `npm run build`를 통과해야 한다.
- **배포**: Vercel에 배포하고, 환경 변수는 Vercel 프로젝트 설정에서 관리한다.

## 7. 구현 단계 (MVP)

1. **Notion API 연동 및 환경 설정**
   - `@notionhq/client` 설치
   - `.env.local`에 `NOTION_API_KEY`, `NOTION_DATABASE_ID` 설정
2. **Notion 데이터베이스 생성 및 API 키 설정**
   - 3장의 속성 구조로 데이터베이스 생성
   - Integration 생성 후 데이터베이스에 연결(공유)
3. **글 목록 페이지 구현**
   - 홈 화면에 발행된 글 목록 표시
4. **글 상세 페이지 구현**
   - 본문 블록 렌더링, 404 처리
5. **스타일링 및 최적화**
   - 반응형 레이아웃, 캐싱, 메타 태그(SEO 기본값) 설정

> 참고: 원래 요청의 MVP 범위(4장 기능 요구사항 4.1~4.6)에는 카테고리 필터와 검색이 포함되어 있다. 위 5단계 목록은 원래 구현 단계를 그대로 옮긴 것이며, 카테고리 필터(4.4)와 검색(4.5)은 3단계 이후 5단계 안에서 함께 구현한다.

## 8. 열린 질문

- [ ] 글 URL의 `slug` 규칙: 제목 기반(한글 인코딩 처리 필요) vs Notion 페이지 ID 기반
- [ ] 캐싱 주기: 글을 발행한 뒤 얼마나 빨리 반영되어야 하는가 (즉시 vs 수 분 단위 허용)
- [ ] 이미지 처리: Notion 이미지 URL은 일정 시간 후 만료되므로, 다운로드 후 저장할지 여부
- [ ] 검색 방식: 글 수가 늘었을 때 클라이언트 필터링으로 충분한지
- [ ] 다크 모드 지원 범위
- [ ] 기존 스타터의 `login`, `signup` 페이지와 관련 컴포넌트를 제거할지 여부

## 9. 성공 기준

- Notion에서 글을 `발행됨`으로 바꾸고 캐시 주기가 지나면, 별도 배포 없이 블로그에 글이 나타난다.
- 초안 글은 어떤 경로로도 노출되지 않는다.
- 모바일과 데스크톱 모두에서 목록, 상세, 카테고리, 검색이 정상 동작한다.
- `npm run check-all`과 `npm run build`가 통과한다.
